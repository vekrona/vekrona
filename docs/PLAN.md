# vekrona: personal Fedora + Sway desktop, recipe plan (post-review)

## Context

The user runs Fedora 44 Workstation on a desktop (Ryzen 7950X3D, RTX 4090, Dell AW3225QF 4K 240 Hz QD-OLED) and today uses Omarchy-on-Fedora (omedora COPR, Hyprland, Omarchy's Quickshell shell). They like parts of Omarchy but want their own opinionated setup: **stability** first, **gaming-ready** second, macOS-like keyboard without breaking terminals.

Deliverable: repo `vekrona/vekrona` (built locally in `~/wrk/vekrona`; push is the user's, SSH agent unreachable from this session) with an idempotent staged `install.sh`, all configs, a README and docs/ recipe. Migrated in place on this machine stage by stage, and smoke-tested in a clean Fedora 44 VM.

Grilled 2026-09-29; three adversarial Opus reviews (system, desktop, installer) applied. Facts verified on this machine or from primary sources unless marked *unverified*.

| 2 | NVIDIA: RPM Fusion `akmod-nvidia`, **proprietary** module, GSP off | Stage 10 only, and only where the proprietary 615 module can drive every NVIDIA GPU (`wants_nvidia_stage`, decided before any package is installed because RPM Fusion's `xorg-x11-drv-nvidia` `%posttrans` blacklists nouveau on install): every NVIDIA display device must have a PCI device ID in `[0x1e00, 0x2900)`, Turing to Ada (pre-Turing Maxwell/Pascal/Volta was dropped after the 580 branch; Blackwell needs the open module with GSP, which this setup disables), and Secure Boot must not block the module (`mokutil --sb-state` enabled and the akmods key `/etc/pki/akmods/certs/public_key.der` not enrolled per `mokutil --test-key` refuses the stage; a missing or failing `mokutil` on a UEFI boot also refuses, naming the reason; a boot without UEFI skips the check). then `grubby --update-kernel=ALL` with the args printed by `nvidia_kernel_args` in `lib/common.sh`: `nvidia.NVreg_EnableGpuFirmware=0 pcie_aspm=off rd.driver.blacklist=nouveau,nova_core modprobe.blacklist=nouveau,nova_core` (`pcie_aspm=off` on desktops only, never on a laptop) (RPM Fusion's own posttrans adds the two blacklist args with the same spelling); assert tokens in `grubby --info=ALL` and `/etc/kernel/cmdline`; 70-verify checks the same args token for token (active on the running cmdline, else pending a reboot, else fail); assert modprobe options + nvidia-suspend/resume/hibernate enabled;
