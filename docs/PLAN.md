# vekrona: personal Fedora + Sway desktop, recipe plan (post-review)

## Context

The user runs Fedora 44 Workstation on a desktop (Ryzen 7950X3D, RTX 4090, Dell AW3225QF 4K 240 Hz QD-OLED) and today uses Omarchy-on-Fedora (omedora COPR, Hyprland, Omarchy's Quickshell shell). They like parts of Omarchy but want their own opinionated setup: **stability** first, **gaming-ready** second, macOS-like keyboard without breaking terminals.

Deliverable: repo `vekrona/vekrona` (built locally in `~/wrk/vekrona`; push is the user's, SSH agent unreachable from this session) with an idempotent staged `install.sh`, all configs, a README recipe. Migrated in place on this machine stage by stage, and smoke-tested in a clean Fedora 44 VM.

Grilled 2026-09-29; three adversarial Opus reviews (system, desktop, installer) applied. Facts verified on this machine or from primary sources unless marked *unverified*.

Alt-BackSpace is deliberately absent from `terminal-word-nav`: inside the three
terminal app_ids, Alt+Backspace is left unmapped so the native ESC DEL byte
Ghostty sends reaches the shell and readline's own `backward-kill-word`
binding deletes the previous word; only Alt-Left/Alt-Right are remapped
there, to Ctrl-Left/Ctrl-Right, for readline's word-movement bindings.
Outside those terminals, `cmd-layer` still maps Alt-BackSpace to
Ctrl-BackSpace. See the README's Cmd layer section for why remapping
Alt-Backspace inside a terminal does not work the same way it does for GUI
apps.

## Verification

`70-verify.sh` receives the effective stage set and asserts per stage: repos/COPRs enabled · driver facts (#2, via sudo/nvidia-smi) · snapper config + cleanup algorithm `number` + a pre/post pair from a `dnf install/remove hello` round-trip · versionlock list ⊇ expected and `.fcNN` matches · `sway --validate` · `xremap-wlroots --validate-config` · `getent passwd greetd` · fonts · flatpak overrides · `scb` present · webapp profiles in profiles.ini. `QSG_RHI_BACKEND` is asserted by the same hardware-conditional branch as `vekrona-gpu.conf`: with the dGPU marker present, the file must set `vulkan` (hard assert); with the marker absent, the variable must be absent from `vekrona.conf`, `vekrona-gpu.conf`, `dms.service.d/vekrona.conf`, the unit's declared `Environment=` (`systemctl --user show dms -p Environment`), and the user manager's own environment (`systemctl --user show-environment`), all hard asserts. Whether `dms.service`'s actual running process agrees (`/proc/<MainPID>/environ`) is checked too, but only as a `warn_check`, not a hard assert: `environment.d` is read once when the systemd --user manager starts, so a `dms.service` already running from before this stage rewrote the file legitimately keeps the old value until the next reboot or re-login, and that lag is not a misconfiguration (the same idiom the nvidia block already uses for its own "reboot pending" checks). When `dms.service` is not running at all, the process check is skipped with a log line, not a warning. None of this needs a graphical session, only `systemctl --user` and file/`/proc` reads, both of which work over SSH or from a text console given a lingering user session. Manual: Hyper+w kills a Firefox window (proves exact_match), Ctrl+c in ghostty = SIGINT, Caps tap = Esc, `systemd-inhibit --list` shows caffeine, mangohud frametimes flat under VRR.

## Known issues (README)

Three pre-1.0 layers on NVIDIA; wlroots in-game flicker on NVIDIA (gamescope isolates); actions plugin under offline `system-upgrade` *unverified* (manual snapshot mandated); `input` group trade-off; Omarchy units/IME leak into Sway until 90b; Qt lock withholds updates; a hung DMS while locked cannot be recovered through IPC or a unit restart, only a reboot, and lock/unlock under Vulkan on the real NVIDIA machine is untested; `pcie_aspm=off` unexplained; DMS windows share one app_id.
